BROWSER TOKEN CONSUMPTION GUIDE
================================

WHAT IS "CONTEXT USED"?
------------------------
"Context used" refers to the token/context window budget you have available. 
Tokens are units of text that AI models process. Browser snapshots consume 
significantly more tokens than regular code reading because they capture 
complete page state information.

WHY BROWSER TOOLS CONSUME SO MUCH CONTEXT
------------------------------------------
When you ask Cursor to "look at browser," it:
1. Captures a full accessibility snapshot of the entire page
2. Includes all visible elements, their properties, and computed styles
3. Stores this as structured data (YAML/JSON format), which is very verbose
4. Can easily consume 5,000-20,000+ tokens per snapshot depending on page complexity

A single browser snapshot can be equivalent to reading 10-50+ code files!

HOW TO OPTIMIZE CONTEXT USAGE
------------------------------

1. BE SPECIFIC ABOUT WHAT YOU NEED
   Instead of: "Look at the browser" (captures everything)
   Try: "Check if the text wraps correctly in the meme generator"
       "See if the template gallery displays properly"
       "Verify the upload button styling"

2. USE CODE READING INSTEAD OF BROWSER WHEN POSSIBLE
   For code-related questions:
   ✓ Read relevant files directly (read_file, grep)
   ✓ Use semantic search (codebase_search)
   ✓ These are MUCH more efficient than browser snapshots
   
   Use browser tools when you need to:
   ✓ See actual rendered output
   ✓ Debug visual layout issues
   ✓ Test interactive behavior
   ✓ Verify responsive design

3. ASK TARGETED QUESTIONS
   Instead of opening browser to "see what's wrong," describe the issue:
   ✓ "The text overflow issue on line X"
   ✓ "The CSS styling for the template gallery"
   ✓ "The JavaScript function that handles text wrapping"

4. USE BROWSER ONLY WHEN VISUAL VERIFICATION IS ESSENTIAL
   Use browser tools for:
   ✓ Visual verification of changes
   ✓ Debugging layout/CSS issues
   ✓ Testing interactive features
   ✓ Responsive design checks
   
   Avoid browser tools for:
   ✗ Code logic questions
   ✗ Understanding function behavior
   ✗ Finding where code is located
   ✗ Reading/editing code

5. LIMIT BROWSER USAGE FREQUENCY
   ✓ Don't refresh browser after every small change
   ✓ Make multiple code changes, then check once
   ✓ Use browser as final verification step, not for exploration

EFFICIENCY COMPARISON
----------------------

LESS EFFICIENT WORKFLOW:
1. "Look at browser" → 15k tokens
2. "Fix the text overflow" → make changes
3. "Look at browser again" → 15k tokens
4. "Check if it works" → 15k tokens
Total: ~45k tokens

MORE EFFICIENT WORKFLOW:
1. "Add line wrapping support for text overflow" → read code, make changes
2. "Look at browser to verify it works" → 15k tokens
Total: ~20k tokens

TOKEN CONSUMPTION ESTIMATES
----------------------------
- Reading a code file: 500-2,000 tokens
- Browser snapshot: 5,000-20,000+ tokens
- Semantic search: 1,000-3,000 tokens
- Grep search: 200-1,000 tokens

BEST PRACTICES FOR YOUR PROJECTS
---------------------------------
✓ Read script.js directly instead of browser for code questions
✓ Use browser only to verify visual results
✓ Describe issues clearly so AI can read relevant code sections
✓ Batch changes before checking in browser
✓ Use browser as final verification, not exploration tool

REMEMBER
--------
Browser tool = Powerful for visual verification
Code reading tools = More efficient for development tasks

Use the right tool for the right job to maximize your context budget!
